# 多多翻译单元测试

## 运行

在项目根目录执行 `swift test`。需要项目已有的 Xcode Command Line Tools 或 Xcode，不需要安装第三方测试框架。

只运行一组测试：

```bash
swift test --filter LearningNoteParserTests
swift test --filter ScreenshotGeometryTests
swift test --filter ShortcutFormatterTests
```

## 覆盖范围

| 测试文件 | 用例数 | 验证内容 |
| --- | ---: | --- |
| [LearningNoteParserTests.swift](../Tests/MacScreenTranslatorTests/LearningNoteParserTests.swift) | 7 | Unicode、多行内容、Markdown 代码块、JSON 前后说明、缺失字段、前导标签清理、保留正文中的标签、非法 JSON 和字段类型 |
| [ScreenshotGeometryTests.swift](../Tests/MacScreenTranslatorTests/ScreenshotGeometryTests.swift) | 8 | Retina 缩放、左下角到左上角坐标换算、屏幕本地选区、越界裁剪、完全在屏幕外、零尺寸、单像素裁剪、分数像素取整、无效尺寸 |
| [ShortcutFormatterTests.swift](../Tests/MacScreenTranslatorTests/ShortcutFormatterTests.swift) | 5 | 默认快捷键、修饰键顺序、忽略无关标志、数字键、未知键码的可读回退 |

部分用例包含多组输入，因此验证场景数多于测试方法数。

## 为测试做的代码调整

- 将原来的学习笔记解析和标签清理抽到 [LearningNoteParser.swift](../Sources/LearningNoteParser.swift)，服务调用完成后仍使用同样的解析规则和错误提示。
- 将截图选区的像素坐标计算抽到 [ScreenshotGeometry.swift](../Sources/ScreenshotGeometry.swift)，保留缩放、纵轴转换、整像素取整和边界裁剪规则，并拒绝无效的屏幕或图像尺寸。
- 在 `Package.swift` 中加入 XCTest 测试 target，通过 `@testable import MacScreenTranslator` 调用内部逻辑。

测试不会实例化 `TranslationStore`，不会读写用户设置、钥匙串或剪贴板，也不会发起翻译请求、截屏或启动 App。

## 验证结果与限制

2026-10-11 执行 `swift test`：20 个 XCTest 用例通过，0 失败。`git diff --check` 通过。

SwiftPM 同时输出的 Swift Testing “0 tests”属于另一个测试运行器；本项目使用的是前面执行的 20 个 XCTest 用例。

首次增加测试时出现的 `AppDelegate.swift` 主线程隔离警告已修复：通知观察者明确指定 `queue: .main`，回调内部使用 `MainActor.assumeIsolated` 访问界面状态，保持原有同步执行顺序。修复后再次运行 20 个 XCTest 用例，全部通过，未再输出这些警告。

这些单元测试不验证真实 OCR 准确率、多显示器实机交互、服务端 HTTP 错误、网络取消和界面行为，相关流程仍需独立验证。

在 Xcode 中打开 `Package.swift` 后，可在测试方法、`LearningNoteParser.parse` 或 `ScreenshotGeometry.cropRect` 上设置断点，运行单个用例，观察输入、清理后的字段或裁剪矩形。
