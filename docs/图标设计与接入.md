完成日期：2026-10-11。

## 2. 把图片转换为 macOS 图标

正式源文件是 [Packaging/AppIcon.png](../Packaging/AppIcon.png)，尺寸为 1024 × 1024，保留透明背景。早期设计稿继续保留，便于对照。

macOS 使用的 [Packaging/AppIcon.icns](../Packaging/AppIcon.icns) 包含多个尺寸，系统可以根据显示位置和屏幕倍率选择对应图片。

[Scripts/build-icon.sh](../Scripts/build-icon.sh) 负责转换：

1. 用系统自带的 `sips` 生成 16、32、128、256、512 像素的普通图片，以及各自的 2 倍图片；最大尺寸为 1024 像素。
2. 按 macOS 约定命名后放进临时 `AppIcon.iconset` 目录。
3. 用系统自带的 `iconutil` 合成为 `Packaging/AppIcon.icns`。
4. 完成后清理脚本创建的临时目录。

不需要安装额外的图片处理软件。

## 3. App 如何加载这个图标

[Packaging/Info.plist](../Packaging/Info.plist) 新增了图标声明：

```xml
<key>CFBundleIconFile</key>
<string>AppIcon</string>
```

这表示应用图标对应资源目录内的 `AppIcon.icns`。

[Scripts/build-app.sh](../Scripts/build-app.sh) 在构建时创建 `Contents/Resources`，把 ICNS 文件复制进去，然后执行原有的签名和签名校验。资源需要在签名之前放入 App，才能一起受到签名保护。

最终产物的相关结构：

```text
dist/MacScreenTranslator.app/
└── Contents/
    ├── Info.plist                  # CFBundleIconFile = AppIcon
    ├── MacOS/MacScreenTranslator   # 可执行文件
    └── Resources/AppIcon.icns      # 正式应用图标
```

这次接入的是应用图标，菜单栏继续使用代码中配置的单色符号。App 的显示名称、主窗口标题、页面标题和菜单提示统一为“多多翻译”。Bundle ID、可执行文件名、App 文件路径和钥匙串标识继续沿用项目配置，以保持应用身份和已有配置稳定。历史设计稿及提示词集中在 `docs/design/icon-history/`，`Packaging/` 只保留正式图标和 plist。

## 4. 本次验证结果

- 正式 PNG 为 1024 × 1024，并包含透明通道。
- ICNS 可以用 `iconutil` 解包，包含普通和 Retina 尺寸；检查了 128 像素版本的构图与字标。
- Shell 脚本语法检查和 plist 格式检查通过。
- Release 构建通过，产物位于 `dist/MacScreenTranslator.app`。
- App 内的图标文件与正式 ICNS 逐字节一致，plist 声明为 `AppIcon`。
- 使用本机现有 Apple Development 证书签名，`codesign --verify --strict --verbose=2` 校验通过。
- `git diff --check` 通过。

构建中仍有现有 `Sources/AppDelegate.swift` 的 Swift 主线程隔离警告。本次 Swift 源码仅替换应用名称相关的展示字符串，没有修改翻译或截图流程。

沙盒内的图标合成、Swift 缓存写入和证书读取受到限制；在获准后于沙盒外运行，相应步骤完成。没有降低签名要求。

这些检查确认了资源已正确打包、签名有效。随后针对空白图标刷新了这份 App 的系统注册信息，并通过 Finder 截图确认小狗图标已经显示；尚未单独验证 Dock。16–32 像素时四字名称会较难阅读，主要依靠小狗轮廓识别。

## 5. 以后如何替换或重新构建

将新的正方形源图放到 `Packaging/AppIcon.png`，然后在项目根目录执行：

```bash
./Scripts/build-icon.sh
./Scripts/build-app.sh
open dist/MacScreenTranslator.app
```

只有替换 PNG 时才需要重新生成 ICNS；日常构建 App 直接使用现有 ICNS。构建脚本沿用本机已有签名身份，在其他机器上可按 README 设置 `CODESIGN_IDENTITY`。

如果 App 已在运行，先从应用菜单正常退出，再打开新构建的 App。

## 6. 已打包但仍显示空白图标

本次正式 App 的位置是 `/Users/yangchenjie/dev/mac-screen-translator/dist/MacScreenTranslator.app`。它已经包含 `Contents/Resources/AppIcon.icns`，不需要手动把 PNG 粘贴到 Finder 的“显示简介”窗口。

发现空白图标后，对这份 App 更新目录时间，并强制刷新它在 Launch Services 中的注册信息，然后重新打开。Finder 已显示新的小狗图标。

以后遇到同样情况，可以在项目根目录执行：

```bash
touch dist/MacScreenTranslator.app
/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister -f "$PWD/dist/MacScreenTranslator.app"
open -R "$PWD/dist/MacScreenTranslator.app"
open "$PWD/dist/MacScreenTranslator.app"
```

上述操作只刷新这份 App 的注册信息，没有清空全系统的图标缓存或重启 Finder、Dock。
